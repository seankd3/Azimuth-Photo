# Settings Feature

Owns: settings read/save/reset, UI settings, settings-page aggregate payloads, and current image flag update endpoints.
Depends on: `web/settings.py`, the `thumbnails` package facade, `web/ai_models.py`, `web/face_worker.py`, `core.requests.json_object`, `features.settings.status` for the aggregate settings status/cache, `data.repositories.images`, `data.repositories.embeddings`, `data.repositories.catalog`, injected DB-path/stat/source-state providers, injected background-task tracker, and injected invalidators.
Public routes: `/api/settings`, `/api/ui/settings`, `/api/image/{image_id}/flag`, `/api/images/flag`, `/api/settings/reset`. The `/settings` HTML page is owned by `features/pages`.
Frontend modules: `static/js/settings/controller.js` owns the Settings public-action `window.PhotoArchive` compatibility adapter; `static/js/settings/actions.js`, `static/js/settings/ai_status.js`, `static/js/settings/cache_status.js`, `static/js/settings/deep_search.js`, `static/js/settings/display.js`, `static/js/settings/form.js`, `static/js/settings/people_status.js`, `static/js/settings/status.js`, `static/js/settings/work_banner.js`, and `static/js/library/flags.js` own lower-level Settings UI/actions.
Data repositories: Flag routes use `data/repositories/images.py` with app-owned cache fanout injected from `web/app.py`. Settings save/reset sync pinned deep-search terms through `data/repositories/embeddings.py` and build returned catalog summaries through `data/repositories/catalog.py`. The aggregate settings status helper also builds its catalog-light summary through `data/repositories/catalog.py`. Settings persistence itself remains in `web/settings.py`.
Tests to run: `cd web && .venv/bin/python -m unittest test_api_shapes test_modular_contracts test_backend -q`.
Do not touch: persisted settings keys, default values, settings response nesting, image flag values, cache/AI/People invalidation side effects, or reset behavior without parity tests.
