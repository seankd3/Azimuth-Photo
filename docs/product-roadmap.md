# Product roadmap

V2 is a deliberate rewrite of a product that never became dependable. The
roadmap therefore advances by complete user surfaces, not feature count or
background-processing coverage.

## Release bar

A surface is complete only when:

- its product sentence is settled;
- it is expressed through the V2 core without a parallel V1 path;
- the machinery it replaces is removed in the same change;
- safety invariants and previously broken behavior are protected;
- it works from an empty application home and against a realistic catalog;
- the running desktop workflow is visually and behaviorally verified;
- errors are visible, actionable, and recoverable;
- the owning documentation describes what now exists.

Passing focused tests, reducing lines, or serving an API response is not a
product completion claim.

## Current program

### 1. Establish a trustworthy baseline

- Reconcile the rewrite branch with the documented core and architecture.
- Restore a meaningful full-suite signal: collection succeeds, optional tools
  skip honestly, and remaining failures are classified by product impact.
- Prove fresh-catalog creation through the real boot path.
- Record the current running-product gaps without treating V1 behavior as a
  requirement merely because it exists.

### 2. Browse, storage, and tiles

Make the first loop genuinely excellent: attach storage, sweep it, render a
combined folder tree and grid, open photographs, follow changed files, and keep
working when the archive is away.

The completion proof covers real working and record drives, cached and uncached
photographs, folder changes, orientation, unavailable originals, cache clearing,
backup, reclaim, Trash, Undo, and restart.

### 3. Import and custody

Rebuild card and folder import around identity, `put`, and one destination rule.
Collision handling, duplicate detection, cancellation, card clearing, video
custody, and interrupted recovery must be understandable and lossless.

### 4. Decisions, culling, and ranking

Keep direct decisions distinct from inferred taste. A comparison round is one
durable action and undo restores it exactly. Selection modes are small pure
strategies over one candidate contract. Embedding coverage may improve ranking
over time but does not block this surface from being correct.

### 5. Develop and export

Preserve only color and editing behavior that can be demonstrated. Remove the
schedulers, histories, caches, and proof machinery whose questions the core no
longer asks. Establish explicit before/after acceptance photographs before
claiming color or renderer parity.

### 6. Search, people, and organization

Build one search and one organizational surface from strong derivatives.
Embeddings, faces, captions, low-level image facts, folders, and collections
remain distinct evidence; fusion happens for a caller rather than destroying
them in one permanent score.

### 7. Installed-product finish

- Replace remaining server/shell seams that exist only for local components to
  communicate.
- Make first run, upgrades, recovery, logs, and failure copy product-quality.
- Complete keyboard, accessibility, responsive, loading, empty, and offline
  states.
- Run the whole working day in the installed Windows app from a clean install.

Only after this step is V2 reviewed for merge, installation, and release.

## Parked until the desktop product earns them

- Full-library embedding backfill as a deadline.
- Android and phone replacement work.
- Hub/satellite synchronization and remote compute.
- Account, pairing, auto-update, and server distribution systems.
- Public publishing expansion and social-platform integrations.

Parked does not mean deleted from history. It means these concerns may not make
the desktop core more complicated before the primary product is finished.

## Health measures

Use measurements that resist gaming:

- concepts required to understand a surface;
- files touched to add one status, kind, or behavior;
- repair blast radius after the rewritten code has aged;
- repair-shaped share of commits;
- interactive latency and resource contention;
- real product failures and recovery quality.

Line count is evidence, not the objective. Static reachability alone is not
permission to delete: inspect operational use, documentation, checks, and git
change history first.
